## Зачем нужен Horizon?

Хорошие материалы разбросаны по лентам, форумам и соцсетям, а внимание не бесконечно. Horizon собирает их, отсеивает лишнее и убирает дубли, а то, что стоит прочитать, приносит вам вместе с контекстом и обсуждением в сообществе.

От ваших интересов зависит и то, что вы читаете, и то, что хотите из этого вынести. В новости важно, «почему это важно», а в инженерном разборе — «что я могу применить». **Профили** Horizon задают для каждого типа контента свои критерии оценки и формат вывода, поэтому дайджест выглядит как собранный вручную.

## Возможности

- **📡 Все источники в одном месте** — RSS, Hacker News, Reddit, Telegram, X, GitHub, финансовые новости и другое.
- **🎯 Решайте, что стоит читать** — задавайте критерии оценки в профилях, отдельные пороги и объединение повторяющихся сюжетов внутри профиля.
- **🧩 Подходящий формат для каждого материала** — краткое содержание, контекст, решение или выводы задаются Markdown-промптами и JSON-описанием блоков.
- **💬 Больше, чем заголовок** — контекст из веб-поиска и обсуждение в сообществе там, где они помогают понять новость.
- **⚖️ Место для всех интересов** — ограничение длины дайджеста и доли каждой категории, чтобы одна громкая тема не вытесняла остальные.
- **📬 Читайте там, где вам удобно** — дайджесты на русском, английском и китайском в Markdown, публикация на Pages, доставка по email и через webhook.

### Один дайджест, разные способы чтения

Профиль — это набор редакционных правил, который можно переиспользовать: **что сюда относится, что стоит оставить и что написать.** Встроенные примеры:

| Что вы читаете | Профиль | Что получаете |
|---|---|---|
| Новости технологий | `tech-news` | Суть события и контекст, при необходимости влияние и обсуждение в сообществе |
| Инженерные разборы | `tech-blog` | Контекст, решение и практические выводы |
| Материалы для авторов контента об ИИ | `ai-creator` | Краткое содержание, при необходимости актуальные поводы и идеи для контента |

Назначьте профиль источнику или доверьте выбор ИИ. Нужен другой взгляд? Адаптируйте существующий профиль, обычно без изменений в Python. [Настроить профиль под себя →](docs/profiles.md)

## Как это работает

![Архитектура Horizon: десять источников поступают в конвейер на основе профилей с инструментами поиска по истории и по вебу, результат доставляется в Markdown, Pages, email, WeChat и webhook.](docs/assets/architecture.svg)

[Исходник схемы для OmniGraffle](docs/assets/architecture.graffle)

**Профили определяют обработку, а настройки запуска отражают ваши предпочтения в чтении.** Каждый материал попадает ровно в один профиль. Анализ, фильтрация и удаление дублей выполняются до обогащения, после чего отобранные материалы собираются в дайджест, сгруппированный по профилям.

Запускайте весь конвейер через CLI или дайте ИИ-ассистенту вызывать отдельные этапы через [MCP](src/mcp/README.md).

## Навык для агента

Пусть ИИ-ассистент сам настроит источники, адаптирует профили и запустит Horizon:

```bash
npx skills add Thysrael/Horizon --skill horizon -g
```

[Установка и использование](docs/agent-skill.md) · [Скачать навык (ZIP)](https://thysrael.github.io/Horizon/downloads/horizon-skill.zip)

Для команды нужен Node.js 22.20+. Затем попросите ассистента установить и настроить Horizon или следуйте инструкции «Быстрый старт» ниже.

## Быстрый старт

### 1. Установка

**Вариант A: локальная установка**

```bash
git clone https://github.com/Thysrael/Horizon.git
cd Horizon

# Установка через uv (рекомендуется)
uv sync

# При необходимости зависимости для тестов и разработки
uv sync --extra dev

# Или через pip
pip install -e .
```

`dev` сейчас объявлен в `pyproject.toml` как необязательный набор зависимостей, поэтому для pytest и других инструментов разработки используйте `uv sync --extra dev`.

Если нужен необязательный источник финансовых новостей OpenBB, установите и его набор зависимостей:

```bash
uv sync --extra openbb
```

Если `openbb` на вашей машине тянет пакеты без готовых wheel-сборок, установите SDK вручную только из бинарных пакетов:

```bash
uv pip install --only-binary=:all: openbb openbb-benzinga
```

**Вариант B: Docker**

```bash
git clone https://github.com/Thysrael/Horizon.git
cd Horizon

# Необязательно: сборка с дополнительными наборами через запятую перед первым запуском
docker compose build --build-arg EXTRAS=openbb horizon
```

Извлечение полного текста через `trafilatura` входит в базовую установку. Набору `twitter` дополнительно нужны браузер Playwright и системные пакеты, которые текущий Dockerfile не устанавливает.

### 2. Настройка

**Вариант A: интерактивный мастер (рекомендуется)**

```bash
uv run horizon-wizard
```

Мастер спрашивает о ваших интересах (например, «LLM inference», «встраиваемые системы», «web security») и автоматически создаёт `data/config.json`. Параметры CLI описаны в разделе [Interactive Wizard](docs/configuration.md#interactive-wizard). Интерфейс мастера на английском. Русские ключевые слова есть только в локальном `data/presets.json`, который используется офлайн (`HORIZON_OFFLINE=1`) или когда API пресетов недоступен.

Подписчики ChatGPT с подходящим тарифом могут выбрать `openai-chatgpt` и пользоваться своим планом через [Sign in with ChatGPT](docs/chatgpt.md) без ключа OpenAI API.

**Вариант B: ручная настройка**

```bash
cp .env.example .env          # Добавьте свои ключи API
cp data/config.example.json data/config.json  # Настройте свои источники
```

Минимальная ручная конфигурация:

```jsonc
{
  "ai": {
    "provider": "openai",
    "model": "gpt-4",
    "api_key_env": "OPENAI_API_KEY",
    "languages": ["ru"]
  },
  "sources": {
    "rss": [
      {
        "name": "Simon Willison",
        "url": "https://simonwillison.net/atom/everything/",
        "profile": "tech-news"
      }
    ]
  },
  "processing": {
    "profiles_dir": "profiles",
    "default_profile": "tech-news",
    "profile_settings": {
      "tech-news": {
        "threshold": 7.0,
        "topic_dedup": true
      }
    }
  }
}
```

Язык дайджеста задаётся в `ai.languages`. Для русского укажите `["ru"]`, для нескольких языков сразу, например, `["ru", "en"]`.

Если у источника явно указан `profile`, используется именно этот профиль. Если поле не указано или равно `"auto"`, ИИ сам сопоставит материал со всеми доступными профилями. Массив вида `["tech-news", "finance-news"]` ограничивает выбор ИИ этими профилями. Устройство и поведение профилей описаны в [Processing Profiles](docs/profiles.md). Пользовательские настройки профиля, например пороги оценки и объединение похожих тем, задаются в `processing.profile_settings`, а не в файлах профилей.

**Сбалансированный дайджест (необязательно)**

Ограничьте размер итогового дайджеста и не дайте одной категории занять его целиком. Категории берутся из конфигурации источников, например `sources.rss[].category`.

```jsonc
{
  "digest": {
    "max_items": 20,
    "category_groups": {
      "ai": {
        "limit": 5,
        "categories": ["ai-news", "ai-tools", "machine-learning"]
      },
      "finance": {
        "limit": 5,
        "categories": ["finance", "business", "equities"]
      }
    },
    "default_group": "other",
    "default_group_limit": 3
  }
}
```

Лимиты групп применяются после фильтрации по профилям и до обогащения. Если `category_groups`, `max_items` и `default_group_limit` не заданы, ограничения не действуют.

`api_key_env` — это имя переменной окружения, а не сам ключ API. Настоящий секрет положите в `.env`:

```bash
OPENAI_API_KEY=sk-your-key
```

Для Gemini используйте `GOOGLE_API_KEY`:

```jsonc
{
  "ai": {
    "provider": "gemini",
    "model": "gemini-2.0-flash",
    "api_key_env": "GOOGLE_API_KEY"
  }
}
```

Любое строковое значение в `data/config.json` может ссылаться на переменные окружения через `${VAR_NAME}`. Это удобно для `ai.base_url`, адресов приватных RSS-лент, адресов webhook или собственных шаблонов заголовков.

Полный справочник — в [руководстве по настройке](docs/configuration.md).

### 3. Запуск

**A. Локальная установка**

```bash
uv run horizon [OPTIONS]
```

**B. Docker**

```bash
docker compose run --rm horizon [OPTIONS]
```

| Параметр | По умолчанию | Описание |
|--------|---------|-------------|
| `--hours N` | 24 | Собрать материалы за последние N часов |
| `-d`, `--data-dir PATH` | `data` | Путь к каталогу данных |
| `-c`, `--config PATH` | `<data-dir>/config.json` | Путь к файлу конфигурации |
| `-l`, `--log-level LEVEL` | `WARNING` | Уровень логирования (DEBUG/INFO/WARNING/ERROR/CRITICAL) |

`--data-dir` меняет каталог состояния: дайджесты, подписчиков и расположение конфигурации по умолчанию. `--config` меняет только файл конфигурации. Готовый дайджест сохраняется в `data/summaries/` (или в `<data-dir>/summaries/`, если задан `--data-dir`). Как сочетать оба флага и создать конфигурацию в своём месте, описано в разделе [Configuration Paths](docs/configuration.md#configuration-paths).

### 4. Автоматизация (необязательно)

Запускайте Horizon по расписанию через **GitHub Actions** с помощью [шаблона ежедневного workflow](.github/workflows/daily-summary.yml.disabled). В этом репозитории шаблон отключён: настройте его под своё окружение и переименуйте в `daily-summary.yml`, чтобы включить.

## Куда доставляется дайджест

Horizon может публиковать или доставлять готовый дайджест несколькими способами:

| Канал | Что делает |
|---------|--------------|
| **Сайт на GitHub Pages** | Копирует готовый Markdown в `docs/`, чтобы GitHub Pages публиковал ежедневно обновляемый сайт с дайджестами |
| **Рассылка по email** | Отправляет дайджест подписчикам и обрабатывает подписку и отписку через SMTP/IMAP |
| **Уведомления через webhook** | Отправляет результат (успех или ошибку) в Feishu/Lark, DingTalk, Slack, Discord, Telegram или на любой свой webhook |
| **Уведомления в WeChat** | Отправляет дайджесты через iLink Bot после входа по QR-коду и вашего сообщения боту; действуют лимиты WeChat на ответы |

Настройка доставки описана в [руководстве по настройке](docs/configuration.md). Чтобы запускать этапы конвейера из ИИ-ассистента, используйте **MCP-сервер**: [инструменты](src/mcp/README.md) · [настройка клиента](src/mcp/integration.md).
